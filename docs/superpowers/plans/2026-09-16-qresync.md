# Item 5: QRESYNC — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Learn which messages were deleted from the server instead of inferring it from a message count, so a delete that arrives alongside a new message is not missed.

**Architecture:** `fetch_changed_flags` becomes a QRESYNC-aware call: `ENABLE QRESYNC`, then `SELECT <folder> (QRESYNC (<uidvalidity> <modseq>))`, reading the untagged responses `imap-proto` already parses — it has `Response::Vanished { earlier, uids }` (`parser/rfc7162.rs`). Any failure falls back to today's `select_condstore` path with no vanished list, and `sync_condstore` keeps its count heuristic for exactly that case.

**Tech Stack:** Rust, `async-imap` 0.11.2 (`run_command_and_check_ok`, `run_command_untagged`, `read_response`), `imap-proto` 0.16.7.

**Spec:** `docs/superpowers/specs/2026-09-16-mailcow-native-design.md`

## Global Constraints

- The fallback is not optional: a server without QRESYNC, or a response we cannot parse, must sync exactly as it does today.
- `vanished: None` means "the server did not tell us", which is different from `Some(vec![])`, "nothing vanished". The count heuristic runs only for `None`.
- Deletions are applied by UID, never by sequence number.

/// Largest number of UIDs a single VANISHED range may expand to. A folder with
/// more deletions than this resyncs the slow way instead, which is correct and
/// bounded — unlike allocating whatever the server claimed.
const MAX_RANGE_SPAN: u64 = 100_000;

pub fn select_command(folder: &str, uid_validity: u32, modseq: u64) -> String {
    let escaped = folder.replace('\\', "\\\\").replace('"', "\\\"");
    format!("SELECT \"{escaped}\" (QRESYNC ({uid_validity} {modseq}))")
}

pub fn expand_ranges(ranges: &[std::ops::RangeInclusive<u32>]) -> Vec<u32> {
    let mut out = Vec::new();
    for r in ranges {
        let span = u64::from(*r.end()).saturating_sub(u64::from(*r.start())) + 1;
        if span > MAX_RANGE_SPAN {
            return Vec::new();
        }
        out.extend(r.clone());
    }
    out
}
```

        // QRESYNC folds "what changed" and "what vanished" into the SELECT.
        // Anything unexpected — no capability, a parse we don't recognise —
        // falls back to the CONDSTORE path, which is what shipped before.
        if session.run_command_and_check_ok("ENABLE QRESYNC").await.is_ok()
            && session
                .run_command_untagged(qresync::select_command(folder, uid_validity, since_modseq))
                .await
                .is_ok()
        {
            let mut changed = Vec::new();
            let mut vanished = Vec::new();
            let mut highest = 0u64;
            while let Ok(Some(resp)) = session.read_response().await {
                match resp.parsed() {
                    Response::Vanished { uids, .. } => {
                        vanished.extend(qresync::expand_ranges(uids));
                    }
                    Response::Fetch(_, attrs) => { /* collect uid + flags as the CONDSTORE path does */ }
                    Response::Done { .. } => break,
                    _ => {}
                }
            }
            self.cache.release(creds, session);
            return Ok(ChangedFlags { changed, vanished: Some(vanished), highest_modseq: highest });
        }
```
